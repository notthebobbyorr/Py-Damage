# Hitter popout pitch splits — 2026-10-20

Added a plain Pitch Type Splits table below the existing official season totals
in individual hitter popouts. Updated to four rows: Fastball (source group FA,
type FA or FC), Sinker (source group FA, type SI or FT), Breaking (source group
SL/CU), and Offspeed (source group CH). Hard cutters stay in Fastball; cutters
classified as breaking pitches stay in Breaking. Source SI pitches with an SP
subtype remain in Sinker. Other app pitch-group classifications are unchanged.

Counts and metrics use regular-season pitches for the same player, season, and
level across teams. `#` counts pitches; `%` divides that count by all pitches
seen, including unknown groups. Shares may therefore sum to less than 100%.
`Whiff%` is 100 times whiffs divided by swings, with a blank for no swings.
Hitting metrics reuse `build_hitters`; Swing (%) is swings divided by pitches.
There are no percentile colors, baserunning metrics, identity columns, Max EV,
pSwing, or Whiff vs. Secondaries / Whiff vs. 95+ columns in the new section.

The saved compact output is `data/output/hitter_pitch_splits.parquet`.
Daily refresh rebuilds the current season from saved pitches and preserves
historical seasons. For a backfill, run the following with the project Python:

```
python pipeline/build_hitter_pitch_splits.py --input <historical.parquet> <current.parquet>
```

The builder reads one season and level at a time and replaces output atomically.
It rejects duplicate identities before replacing the saved output. Missing
tracking values and undefined rates display as em dashes. A missing output file
leaves the existing official line available. The What's New page was not updated.

## Team and league tabs — 2026-10-20

Team Hitting and League Hitting each have a standalone Pitch Type Splits tab,
with level and season filters and team selection where applicable. These use
the Pitch Type filter to show any combination of the four groups (All by default).
Filtering rows does not recalculate pitch shares. Both tables retain
the same plain metric columns as hitter popouts. Regular-season pitches are
pooled by batting team/season/level or season/level; traded players contribute
only their pitches for the respective batting team. Rates use pooled counts,
and EV90th is recalculated from the underlying exit velocities. Team aliases
are normalized before aggregation. Unknown pitch groups remain in share totals.

Daily refresh builds all three scopes. To backfill the additional outputs, run
the builder above with `--scope team` and then `--scope league`. These write
`team_hitting_pitch_splits.parquet` and `league_hitting_pitch_splits.parquet`.
The shared hitter aggregator accepts grouping keys for pooled metrics and skips
player position summaries in that case. Existing player callers are unchanged.
Team coverage currently includes MLB for 2015–2026. Numeric minor-league team
codes are excluded consistently with the existing team tables; league outputs
include available minor-league levels because they do not require team codes.
Pitches without an assigned team are also retained in league totals, so league
counts can exceed the sum of named-team counts.

## Verified game classifications — 2026-10-21

An audit matched every saved hitter, team, and league split's pitch count and
percentage denominator to explicit regular-season source rows. The apparent
spring-training leakage was instead 15 minor-league games mislabeled as MLB in
the raw 2026 source: 14 Triple-A games and one Single-A game. MLB schedule
metadata verified 1,629 suspect games; the remaining 1,614 were correctly MLB.

The pitch-split builder now checks games labeled MLB with missing/numeric team
codes against `https://statsapi.mlb.com/api/v1/schedule?hydrate=team`. Verified
game types and levels are cached in `pitch_split_game_metadata.parquet` under
`data/output`, and applied before season/level partitioning and aggregation.
Only explicit `game_type == R` rows are eligible; missing/unknown types cannot
default to regular season. Identical resumed-game entries are deduplicated;
conflicting or missing metadata aborts the build before split files are replaced.

All three split outputs are rebuilt; new suspect games are checked during daily
refresh. Pre-correction split files are backed up in
`data/backups/pitch_split_level_correction/`. This correction is applied to
pitch-type splits; the raw source and other season tables are not rewritten.


## Combined splits and workload bounds — 2026-10-21

Hitters, Pitchers, and Individual Pitches → Splits include a Combined Splits tab.
Choose multiple dimensions: opposing handedness, home/away, and half or month;
hitters can also include pitch group. Metrics are recomputed from the actual
pitch intersection. Individual pitch usage uses all pitcher pitches in that
same intersection, before the display's pitch-type filter. Hitter group shares

`pipeline/build_combined_splits.py` generates regular-season-only partitions

Verified game classifications apply before grouping. The UI loads only selected
seasons, level, and dimensions. Half and month cannot be selected together;
2020 has no All-Star half classification, matching existing split definitions.
Models are not retrained, and season-level model predictions are not substituted
for unavailable intersection predictions. Team filters select affiliations
within the slice; they do not recalculate a traded player's row for one team.

Every split leaderboard defaults to a minimum of 100 pitches. Filter By also
supports PA (hitting), TBF/GS/IP (pitching), and BBE where applicable. Pitch-type
pitching rows use TBF/GS/IP across all pitch types in the selected slice. BBE
and pitch minimums apply to the individual row. Maximum filters are shared by
all standard tables and accept multiple caps, including zero GS. Player tables
also expose explicit regular-season workload caps when a count is omitted from
the display; MLB-equivalent comparisons use actual source-level workload.
Downloads following standard table rendering include the selected caps.

Observed Swing% is swings / pitches throughout Individual Pitches: Shapes,
AR (observed pass-through), percentile views (their percentile convention),
comparison target/results, single splits, combined splits, and gamelogs.
Date-range totals sum swings and pitches before dividing, including Raw counts
mode. No inferred or modeled swing probabilities substitute for observed swings.

`pipeline/backfill_split_workloads.py` adds workload counts and observed swing

It also adds PA to hitter/team/league pitch-group files. Backups are retained

indices produced by Polars, preserving categorical data for pandas.

Daily refresh generates current-season combined partitions and refreshes these
counts after stitching. Existing history is retained. The What's New page remains
unchanged, as requested.

## Hitter split tracking columns and application-wide miss distance

All four legacy hitter split tables now show the existing bat-tracking metrics,
using the same column labels as pitch-group and combined splits. Team hitting
split tables also expose those measurements.

Avg Miss Distance (in.) is available in hitting and pitching season, after-
regression, percentile, comparison, split, combined split, pitch-group, game-log,
date-range, team, league, and park views. Changes views offer it as a metric.
Baserunning and MLB-equivalency tables are excluded, as requested. Miss distance
is an observed mean alongside regressed statistics; no new model/prior is fitted.

The source is Savant's miss_distance: the closest separation between the upper
half of the bat and the ball, in inches, on measured missed swings. Definition:
https://baseballsavant.mlb.com/leaderboard/bat-tracking/swing-timing-miss-distance
Missing measurements stay blank, contribute no sample weight, and never become
zero-distance swings. Every aggregate retains miss_distance_n internally.
Team game logs and date-range summaries weight player/game means by this recorded
sample count. The column participates in existing sorting, numeric filtering,
plotting, and CSV downloads.

The scraper cache and enriched raw files now retain miss_distance. Matching the
saved history and the September 19–October 20 continuation supplied 184,087
historical and 77,673 current-season measurements. The database pull also selects
miss_distance when available, with a null-safe lookup for database schemas without
that field. Existing refresh stages preserve the measurement through aggregation,
game logs, observed regression passthrough, and compact split partitions.

pipeline/backfill_miss_distance.py updates the statistic without rebuilding other
metrics. All 1,483 generated table/chunk/partition files were compared against
their originals: existing values, row counts, and row order match exactly.
Backups and the complete file list are under
data/backups/miss_distance/20261022T034711/; validation is recorded in
outputs/miss_distance_validation.json. Source aggregation checks compare actual
hitter, pitcher, and pitch-type means and sample counts against raw pitches.
Page checks cover 26 hitting/pitching views, with the custom inline table renderer
disabled only inside Streamlit AppTest. What's New remains unchanged; no Git push.

Miss-distance color direction is lower = green / higher = red for hitters, and
lower = red / higher = green for pitchers and individual pitches, including teams
and league views. Tables and continuous plot colors share the same role-specific
rule, including pages with their own reversed-column lists. Plain tables remain
uncolored.

Percentile pages display Avg Miss Distance Pctile on the existing 1–100 scale.
Hitters rank lower raw distances higher; pitchers and individual pitches rank
higher raw distances higher. Both Constant and Customizable modes use their
existing qualification thresholds and grouping rules. Missing measurements remain
blank. Percentile colors consistently show higher ranks green and lower ranks red;
the role-specific inversion is applied once, when ranking the raw measurements.
